# Лекція 12: Формати збереження розріджених матриць: COO, CSR, CSC та LIL

## 1. Теоретична частина

### Як комп'ютер зберігає розріджену матрицю?

У попередній лекції ми переконалися, що в розрахункових моделях енергосистем понад 99% елементів матриць $Y_{bus}$ або матриць Якобі $J$ є нулями. Зберігати їх у вигляді звичайного двовимірного масиву `double[N, N]` неприпустимо через колосальні втрати пам'яті.

Виникає фундаментальне інженерне запитання: **як організувати структури даних у пам'яті комп'ютера, щоб зберігати тільки ненульові значення разом з їхніми координатами, забезпечивши максимальну швидкість обчислень?**

У наукових пакетах обчислювальної лінійної алгебри та промисловому софті для аналізу енергосистем (PSS/E, PowerFactory, OpenDSS, MATPOWER) використовуються спеціалізовані **розріджені формати (Sparse Formats)**. Кожен з них оптимізований під певний клас операцій.

---

### Чотири фундаментальні формати

#### 1. Трійковий формат координат: COO (Coordinate Format)
Найпростіший та найбільш інтуїтивний формат. Матриця зберігається у вигляді трьох паралельних одновимірних масивів однакової довжини $N_{nz}$:
- `rows[]` — індекси рядків;
- `cols[]` — індекси стовпців;
- `values[]` — числові значення елементів.

**Приклад:** Якщо ЛЕП з'єднує вузол 2 та вузол 4 з взаємною провідністю $-j15$, записується трійка `(row: 2, col: 4, val: -15.0)`.

* **Переваги:** Максимально простий запис. Ідеально підходить для початкового формування моделі мережі під час зчитування файлу паспорта ЛЕП та трансформаторів.
* **Недоліки:** Неефективний для математичних операцій (множення, розв'язання систем), оскільки для знаходження сусідів вузла потрібно сканувати весь масив.

---

#### 2. Стиснений рядок: CSR (Compressed Sparse Row)
**Стандарт де-факто** для обчислень в енергетиці, зокрема для множення матриці на вектор ($I = Y \cdot U$) та обчислення поправок у методі Ньютона-Рафсона.

Утискає масив індексів рядків `rows[]` до компактного масиву покажчиків рядків `row_ptr[]` довжиною $N + 1$:
1. `values[]` (довжина $N_{nz}$) — значення всіх ненульових елементів, записаних послідовно рядок за рядком (зліва направо).
2. `col_indices[]` (довжина $N_{nz}$) — відповідні номери стовпців для кожного значення.
3. `row_ptr[]` (довжина $N + 1$) — індекси в масивах `values` та `col_indices`, з яких починається кожен рядок:
   - Елементи рядка $i$ розташовані в діапазоні від `row_ptr[i]` до `row_ptr[i+1] - 1`.
   - Кількість ненульових елементів у рядку $i$ дорівнює: $\Delta = \text{row\_ptr}[i+1] - \text{row\_ptr}[i]$.
   - Останній елемент `row_ptr[N]` завжди дорівнює загальній кількості $N_{nz}$.

> **Нотатка від професора: Чому CSR такий блискавичний?**
>
> Уявіть, що ви шукаєте книгу в бібліотеці. 
> - У форматі **COO** вам довелося б переглянути загальний список усіх 100 000 карток.
> - У форматі **CSR** масив `row_ptr` — це покажчик номерів полиць. Щоб знайти всі ЛЕП, підключені до підстанції №47, процесор миттєво дивиться на `row_ptr[47]` та `row_ptr[48]`. Це дає точну ділянку пам'яті в кеші процесора без жодного зайвого пошуку. Доступ до всіх сусідів вузла виконується за час $O(1)$!

> **Глибока інтуїція: Апаратний рівень (CPU Cache)**
> Чому саме CSR такий ефективний для обчислень? Відповідь лежить в архітектурі сучасних процесорів. Оперативна пам'ять (RAM) працює відносно повільно. Процесор читає дані не по одному числу, а блоками — "кеш-лініями" (Cache Lines, зазвичай 64 байти). 
> Коли алгоритм починає обробляти $i$-й рядок матриці у форматі CSR, всі необхідні значення `values` та `col_indices` розташовані в пам'яті **строго послідовно**. Процесор завантажує цілу кеш-лінію і миттєво виконує серію множень. Якби ми зберігали дані хаотично (як у LIL чи DOK), процесор страждав би від постійних "промахів кешу" (Cache Misses), чекаючи на дані з повільної RAM, що знизило б швидкість обчислень у 10–50 разів!

---

#### 3. Стиснений стовпець: CSC (Compressed Sparse Column)
Дзеркальний аналог CSR, але стиснення виконується по **стовпцях**:
- `values[]` (довжина $N_{nz}$) — ненульові елементи стовпець за стовпцем;
- `row_indices[]` (довжина $N_{nz}$) — номери рядків для кожного значення;
- `col_ptr[]` (довжина $N + 1$) — покажчики початків стовпців.

* **Де використовується:** Більшість сучасних прямих розв'язувачів СЛАР (SuperLU, SuiteSparse, UMFPACK), які виконують LU-факторизацію матриці Якобі, вимагають подання матриці саме у форматі **CSC**, оскільки виключення Гауса найзручніше вести по стовпцях з вибором ведучого елемента (Pivoting).

---

#### 4. Динамічні формати: LIL (List of Lists) та DOK (Dictionary of Keys)
- **LIL (List of Lists):** Кожен рядок матриці представлений окремим динамічним списком пар `(col, val)`.
- **DOK (Dictionary of Keys):** Асоціативний масив (хеш-таблиця), де ключем є пара `(row, col)`, а значенням — число `val`.

* **Де використовується:** При оперативних перемиканнях у мережі (відключення аварійної ЛЕП, комутація секційного вимикача). У форматах CSR/CSC зміна структури вимагає повної перебудови масивів покажчиків, тоді як LIL та DOK дозволяють вставляти або видаляти ненульові елементи на льоту за час $O(1)$.

---

### Порівняльна таблиця форматів

| Критерій | COO | CSR | CSC | LIL / DOK |
| :--- | :---: | :---: | :---: | :---: |
| **Обсяг пам'яті** | $2 \cdot N_{nz} \cdot \text{int} + N_{nz} \cdot \text{float}$ | $(N_{nz} + N + 1)\text{int} + N_{nz} \text{float}$ | $(N_{nz} + N + 1)\text{int} + N_{nz} \text{float}$ | Оверхед списків / хешів |
| **Побудова матриці "з нуля"** | Дуже швидко ($O(1)$ на гілку) | Повільно | Повільно | Швидко ($O(1)$) |
| **Множення на вектор ($A \cdot x$)** | Повільно | **Найшвидше ($O(N_{nz})$)** | Повільніше | Середньо |
| **Вирізання рядка ($A[i, :]$)** | $O(N_{nz})$ | **Миттєво ($O(1)$)** | $O(N_{nz})$ | Швидко |
| **Динамічна зміна топології** | Незручно | Складно (потрібна перебудова) | Складно | **Найзручніше** |

### Приклад ручного розрахунку: Упаковка матриці 4-вузлової мережі

Розглянемо фрагмент мережі 4 вузлів (індексація з 0: вузли 0, 1, 2, 3):
- ЛЕП 0-1 ($b = 10$)
- ЛЕП 1-2 ($b = 20$)
- ЛЕП 2-3 ($b = 15$)
- ЛЕП 0-3 ($b = 5$)

Матриця вузлових провідностей $Y$ (4x4):
```
      0      1      2      3
0 [  15.0  -10.0    0.0   -5.0 ]
1 [ -10.0   30.0  -20.0    0.0 ]
2 [   0.0  -20.0   35.0  -15.0 ]
3 [  -5.0    0.0  -15.0   20.0 ]
```

Підрахунок: $N = 4$ вузли, $N_{nz} = 12$ ненульових елементів.

#### 1. Представлення у форматі COO (12 трійок):
- `rows   = [  0,    0,   0,     1,    1,    1,     2,    2,    2,     3,    3,    3 ]`
- `cols   = [  0,    1,   3,     0,    1,    2,     1,    2,    3,     0,    2,    3 ]`
- `values = [ 15,  -10,  -5,   -10,   30,  -20,   -20,   35,  -15,    -5,  -15,   20 ]`

#### 2. Представлення у форматі CSR:
1. Масив значень `values` (розмір 12):
   `[ 15.0, -10.0, -5.0,  -10.0, 30.0, -20.0,  -20.0, 35.0, -15.0,  -5.0, -15.0, 20.0 ]`
2. Масив стовпців `col_indices` (розмір 12):
   `[  0,     1,     3,     0,    1,     2,     1,    2,     3,     0,     2,    3  ]`
3. Масив покажчиків рядків `row_ptr` (розмір $N + 1 = 5$):
   - Рядок 0 починається з індексу 0: `row_ptr[0] = 0` (має 3 елементи, до індексу 3)
   - Рядок 1 починається з індексу 3: `row_ptr[1] = 3` (має 3 елементи, до індексу 6)
   - Рядок 2 починається з індексу 6: `row_ptr[2] = 6` (має 3 елементи, до індексу 9)
   - Рядок 3 починається з індексу 9: `row_ptr[3] = 9` (має 3 елементи, до індексу 12)
   - Завершальний покажчик: `row_ptr[4] = 12` ($N_{nz}$)

Отже: `row_ptr = [ 0, 3, 6, 9, 12 ]`.

## 2. Приклад розрахунку на C#

Нижче наведено самостійну C# реалізацію структури `CsrMatrix`, яка упаковує топологію енергосистеми у три базові масиви CSR, виконує пряме множення на вектор напруг і порівнює результат з вбудованим розрідженим класом `MathNet.Numerics`.

```csharp
// Program.cs
using System;
using System.Collections.Generic;
using MathNet.Numerics.LinearAlgebra;
using MathNet.Numerics.LinearAlgebra.Double;

public class Program
{
    // Клас розрідженої матриці у форматі CSR
    public class CsrMatrix
    {
        public int Rows { get; }
        public int Cols { get; }
        public double[] Values { get; }
        public int[] ColIndices { get; }
        public int[] RowPtr { get; }

        public CsrMatrix(int rows, int cols, double[] values, int[] colIndices, int[] rowPtr)
        {
            Rows = rows;
            Cols = cols;
            Values = values;
            ColIndices = colIndices;
            RowPtr = rowPtr;
        }

        // Швидке розріджене множення на вектор: y = A * x
        public double[] Multiply(double[] x)
        {
            if (x.Length != Cols)
                throw new ArgumentException("Невідповідність розмірності вектора!");

            double[] y = new double[Rows];

            // Проходимо по кожному рядку за допомогою покажчиків row_ptr
            for (int i = 0; i < Rows; i++)
            {
                int start = RowPtr[i];
                int end = RowPtr[i + 1];
                double sum = 0.0;

                for (int idx = start; idx < end; idx++)
                {
                    int col = ColIndices[idx];
                    sum += Values[idx] * x[col];
                }
                y[i] = sum;
            }
            return y;
        }

        // Отримання значення елемента A[i, j] за час O(log(k)) або O(k)
        public double GetElement(int i, int j)
        {
            int start = RowPtr[i];
            int end = RowPtr[i + 1];
            for (int idx = start; idx < end; idx++)
            {
                if (ColIndices[idx] == j)
                    return Values[idx];
            }
            return 0.0; // Елемент відсутній — отже, це нуль
        }
    }

    public static void Main(string[] args)
    {
        Console.WriteLine("===============================================================");
        Console.WriteLine("   ЛЕКЦІЯ 12: ФОРМАТИ ЗБЕРЕЖЕННЯ РОЗРІДЖЕНИХ МАТРИЦЬ (CSR)    ");
        Console.WriteLine("===============================================================\n");

        int N = 4; // Кількість вузлів

        // Вхідні масиви формату CSR для 4-вузлової мережі з ручного розрахунку
        double[] values = {
            15.0, -10.0,  -5.0,
           -10.0,  30.0, -20.0,
           -20.0,  35.0, -15.0,
            -5.0, -15.0,  20.0
        };

        int[] colIndices = {
            0, 1, 3,
            0, 1, 2,
            1, 2, 3,
            0, 2, 3
        };

        int[] rowPtr = { 0, 3, 6, 9, 12 };

        // Створюємо екземпляр нашої CSR матриці
        var csr = new CsrMatrix(N, N, values, colIndices, rowPtr);

        Console.WriteLine("--- Структура масивів CSR у пам'яті ---");
        Console.WriteLine("Values     : [" + string.Join(", ", csr.Values) + "]");
        Console.WriteLine("ColIndices : [" + string.Join(", ", csr.ColIndices) + "]");
        Console.WriteLine("RowPtr     : [" + string.Join(", ", csr.RowPtr) + "]\n");

        // Задаємо вектор напруг вузлів U = [1.05, 1.02, 1.01, 1.00]
        double[] U = { 1.05, 1.02, 1.01, 1.00 };

        // Множення власним алгоритмом CSR
        double[] I_csr = csr.Multiply(U);

        Console.WriteLine("--- Результат множення I = Y * U через власну структуру CSR ---");
        for (int i = 0; i < N; i++)
        {
            Console.WriteLine($"Вузол {i + 1} (індекс {i}): Струм I = {I_csr[i],8:F4} А");
        }

        // Перевірка через бібліотеку MathNet.Numerics
        var Y_mathnet = Matrix<double>.Build.Sparse(N, N);
        for (int i = 0; i < N; i++)
        {
            for (int j = 0; j < N; j++)
            {
                double val = csr.GetElement(i, j);
                if (Math.Abs(val) > 1e-9)
                    Y_mathnet[i, j] = val;
            }
        }
        var U_vec = Vector<double>.Build.Dense(U);
        var I_mathnet = Y_mathnet * U_vec;

        Console.WriteLine("\n--- Перевірка через MathNet.Numerics ---");
        Console.WriteLine("I (MathNet) : " + I_mathnet.ToVectorString("F4"));

        // Обчислення похибки
        double error = 0.0;
        for (int i = 0; i < N; i++)
        {
            error = Math.Max(error, Math.Abs(I_csr[i] - I_mathnet[i]));
        }
        Console.WriteLine($"Максимальна абсолютна похибка: {error:E4}");
    }
}
```

## 3. Перевірка правильності обрахунку

1. **Довжина покажчика рядків:** Масив `row_ptr` обов'язково повинен мати довжину $N + 1$.
2. **Монотонність покажчиків:** Елементи масиву `row_ptr` повинні бути строго неспадною послідовністю:
   $$\text{row\_ptr}[0] = 0 \le \text{row\_ptr}[1] \le \dots \le \text{row\_ptr}[N] = N_{nz}$$
3. **Діапазон стовпців:** Усі індекси в масиві `col_indices` мають належати інтервалу $[0, N-1]$.
4. **Співпадіння елементів:** Елемент $A[i, j]$, відновлений через `GetElement(i, j)`, повинен строго збігатися зі значенням вихідної матриці провідностей.
